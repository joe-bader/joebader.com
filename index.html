Professional Experience

Founder & Principal Engineer

Tuner Logic (tunerlogic.com) | Remote

07/2025 - Present

  • Founded Tuner Logic, an AI-assisted SaaS for automotive performance tuning, where a wrong answer can damage an engine. Sole architect of the product and its delivery platform, from concept through production deployment (3,300+ agent-authored commits under my direction and review).
  • Built the product's AI assistant as a server-side agent loop in TypeScript on Cloudflare Workers. The model answers tuning questions by calling 13 typed tools over the user's own calibration, log, and dyno data, with schema-validated output and a hard cap on tool rounds that forces a final answer.
  • Kept the model away from decisions where it could do harm. Corrections and safety checks run in deterministic code that the model calls as tools, model-written values for fuel, ignition, and boost tables are withheld, and no edit is applied until the user reviews and accepts it. Unsafe requests are refused by rule, in ten languages.
  • Made model selection evidence-based with a nightly evaluation that runs every candidate model through realistic tasks and scores the full sequence of tool calls with fixed checks instead of an LLM judge. Results change production routing only through a pull request that a person reviews.
  • Built a model router that balances capability, speed, and cost for each task and uses production telemetry to sideline a model that starts returning malformed tool calls, empty responses, or errors, restoring it once it recovers.
  • Built the multi-agent platform that develops the product: labeling an issue starts a supervised coding agent in its own isolated workspace, using any of six agent CLIs. Agents author 100% of commits, and any session can be watched or taken over from a dashboard or phone.
  • Made long-running agent work recoverable: prompts are queued durably, dispatch is idempotent, and stuck sessions are reclaimed automatically. Several of these safeguards came from diagnosing live failures (leaked worker slots, an exhausted port pool, stalled reviews) and shipping fixes with regression tests.
  • Limited what each agent can do. Coding and review agents have separate scoped identities, so the agent that writes code cannot approve it and the reviewer cannot push. Review agents run in per-session sandboxes without a source checkout and treat pull request content as untrusted input.
  • Automated the path to production without giving up control. A merge queue lands only pull requests approved at their exact commit (250+ batches in its first two weeks), retries infrastructure failures, and isolates the offending change when a batch fails. A Python release broker keeps production credentials out of CI.
  • Held the product to safety-engineering standards: a 100% backend test-coverage floor, ISO 26262-inspired coverage targets for domain code, production health checks every five minutes, and rehearsed restore drills.
