Professional Experience

Founder & Principal Engineer

Tuner Logic (tunerlogic.com) | Remote

07/2025 - Present

  • Founded Tuner Logic, an AI-assisted SaaS for automotive performance tuning, where a wrong answer can damage an engine. Sole architect of the product and its delivery platform, from concept through production deployment (3,300+ agent-authored commits under my direction and review).
  • Built the product's AI assistant in TypeScript on Cloudflare Workers. It answers tuning questions by calling 13 tools that read the user's own calibration, log, and dyno data, checks each response against a fixed format, and limits how many steps it can take.
  • Kept the model away from decisions where it could do harm. Corrections and safety checks are calculated by regular code, not the model. Values the model writes for fuel, ignition, and boost tables are held back, and no edit is applied until the user reviews and accepts it. Unsafe requests are refused by fixed rules, in ten languages.
  • Chose models on evidence. A nightly test runs each candidate model through realistic tasks and checks every step it takes against fixed rules, not another model's opinion. Model changes go through a reviewed pull request, and a model that starts failing in production is removed automatically.
  • Built the multi-agent platform that develops the product. Labeling an issue starts a supervised coding agent in its own isolated copy of the code, using any of six coding-agent tools. Agents author 100% of commits, and any session can be watched or taken over from a dashboard or phone.
  • Made long-running agent work recoverable: instructions are saved before an agent starts, the same task never starts twice, and stuck sessions are cleaned up automatically. Added these safeguards after diagnosing live failures, with tests to prevent repeats.
  • Limited what each agent can do. Coding and review agents use separate accounts with narrow permissions, so the agent that writes code cannot approve it and the reviewer cannot change it. Review agents run in isolated containers and treat the content they review as untrusted.
  • Automated the path to production without giving up control. Changes merge only when the exact version being merged has been approved (250+ batches in the first two weeks). The system retries when infrastructure fails and removes the change that broke a batch. A Python release service keeps production credentials away from the build system.
  • Held the product to safety-engineering standards: 100% test coverage of backend code, targets modeled on the ISO 26262 automotive safety standard, health checks every five minutes, and practiced restores.
